# Parallax: notes for contributors (people and AI assistants)

Parallax is a free, open-source, offline web app that trains visuospatial ability: 20 procedurally generated exercises (six DAT-style formats among them, behind an opt-in focus), 6 held-out probes for the Spatial Check, five progression modes on one learner record, Section practice, a Daily Challenge and play-to-learn tutorials. It was built by the Chimera community on Discord (https://discord.gg/chmr).

Read before changing anything: docs/dev/ARCHITECTURE.md (contracts), docs/dev/EXERCISE-GUIDE.md (how an exercise is built), docs/dev/ENGINE.md (ratings, item choice, modes, the Spatial Check, simulations), docs/dev/PLAN.md (the plan the owner approved: milestones and acceptance), docs/dev/STATE.md (where the work stands), docs/dev/DECISIONS.md (what was decided and why), docs/dev/CONTRACT-v1.2.md (file ownership and interfaces while builders work in parallel), and the user guide docs/Parallax-Guide.pdf (research and references).

## Map of the code
- `index.html` loads every stylesheet and classic script in order (PENDING comment blocks hold files not written yet; `tools/sync-index.py` activates them). No build step is needed to run.
- `js/core/`: `px.js` (namespace, version), `util.js` (incl. `fmtSecs`, the one answer-time format), `rng.js` (seeded PRNG), `bus.js` (events), `timing.js` (frame clock, stutter monitor), `clock.js` (the one active-time clock), `keys.js` (key layers), `store.js` (versioned record, format 3, memory fallback, upgrade hooks, backup `exportJSON`, community export `pooled`, `exportRule`), `router.js` (in-memory routes, hash mirror), `svg.js`, `ui.js` (modals, toasts, buttons, copy with fallback), `stage3d.js` (the one shared three.js renderer).
- `js/engine/` (pure, Node-tested): `model.js` (item-response model, config), `estimator.js` (Gaussian rating, shown level, starter band), `select.js` (item choice, seeds), `staircase.js`, `bandit.js`, `schedule.js` (interleaving stages, automatic choices), `modes.js` (Train, Path, Threshold, Speed, Free play; mode suggestions), `assess.js` (Spatial Check), `achievements.js`, `streak.js` (weekly goal with grace), `daily.js`, `stats.js`, `merge.js` (two tabs), `section.js` (Section practice), `rebase.js` (re-basing stored levels when a band is added), `pace.js` (the Quick deadline staircase).
- `js/ex/registry.js`: the exercise contract (`PX.ex.define`). Each `js/ex/<id>/` has `gen.js` (pure generator, validator, shortcut solvers), `learn.js` (Watch, Try, Go texts, rules card, tips, strategies, bridge) and `view.js` (rendering and input); styles in `css/ex/<id>.css`.
  - Training exercises: track, rotate, spin, fold, nets, slice, views, orient, span, hidden, homing, reckon, knots, centralpoint; DAT-style: openings, patviews, angles, patfold, cubes, form.
  - Probes (Spatial Check only, never trained): cubematch, viewmatch, mechanisms, patterns, level, wordlinks (the verbal control).
- `js/ui/`: `app.js` (boot, shell, export dialog, full welcome or one-tap card), `welcome.js` (`PX.ui.chimera`: link, Copy, invites; the welcome and the card; figures), `home.js` (Today, mode suggestion), `library.js` (Library, exercise pages, `PX.ui.exinfo`, mode "right when" lines), `play.js` (the player: trials, pauses, show-me, summaries, Watch, Try, Go), `check.js`, `section.js`, `progress.js`, `log.js`, `lab.js` (protocols, self-experiment, exports, how the engine works), `settings.js`, `about.js`, `share.js` (cards, texts, challenge codes), `tour.js`, `overlap.js` (test hygiene: notes, helper, PAT focus), `playtest.js` (playtest mode).
- `css/`: `base.css` (tokens, themes), `app.css`, `screens.css`, `play.css`, `section.css`, `playtest.css`, `ex.css`, `ex/<id>.css`.
- `tests/node/` (run.mjs + *.test.mjs, sim.mjs, fixtures/; chimera-dom.mjs is a small fake DOM for UI pieces), `tests/e2e/` (Python Playwright; `pwslot.sh` lock), `tests/dev/harness.html`; `tools/` (build-single, sync-index, shots, build-pdf, vendor-three, privacy_check, githooks); `docs/dev/`; `docs/research/` (notes per version, `ACCESS.md`); `docs/guide/` (guide source) and `docs/Parallax-Guide.pdf`; `dist/Parallax.html` (single-file build).

## Standing rules (they bind every change)
1. **Chimera.** The first launch shows the full welcome: "built by the Chimera community on Discord", a Join button for https://discord.gg/chmr (new tab), and the address with Copy. Later launches show a one-tap card with the same line, Join and close, which covers nothing and never shows during a session. The link stays in the header, the More sheet, the footer, About, the README's first line, the guide, every tutorial end screen and every share text (always the full https address). `PX.ui.chimera.invite` invites the player at natural high points (personal bests, Path passes, grades, achievements, check results, plateaus, exports and backups), at most one per screen and never inside a block of items. Nothing more is said about Chimera than that.
2. **Wording.** Say what the research found, which bets Parallax makes and how it measures them, in a sure and inquisitive tone that asks players to try the bets with us. Promise no outcome: never claim or imply that Parallax raises IQ or makes anyone smarter, or improves grades, work, sport, driving, focus or health. One accurate limit where a claim needs it, never stacked; no section opens with what training cannot do. Levels carry ranges; "unclear yet" is not "no progress"; numbers in texts agree with the code. The near-mid-far ladder governs wording, not design. "DAT score(s)" appears only in negations, with the ADA line beside it.
3. **Test hygiene**: no clones of standard IQ subtests (Wechsler Block Design, Visual Puzzles), no packing tasks, no copyrighted test items. Every item is procedurally generated. DAT-style exercises follow the formats only: never the ADA's questions (recalled or sample ones included), instructions or drawings, never prep products' items, and the marks only to say what a format follows, with the ADA line.
4. **Solver-verified items**: every generator has an independent validator. Exactly one right answer; distractors visibly different; the distinguishing feature visible; mirror distractors chirality-checked. Node tests run at least 10 000 seeds per exercise.
5. **Shortcut solvers**: cheap heuristics (counting, parity, silhouette, odd one out, most like the others) stay within chance + 10 points on every item pool. A scoped exception needs a DECISIONS line and a per-level test.
6. **Runs everywhere**: file://, GitHub Pages, the single-file build, sandboxed srcdoc previews, phones. Classic scripts on window.PX only (no ES modules, no fetch of local files, no workers from files); routing in memory; storage through PX.core.store with a memory fallback; in-app navigation via data-go, never relative hrefs.
7. **Timing validity**: motion from elapsed time; the answer clock starts at the painted frame; no saves or extra work during stimulus phases; voided trials (stutter, pause during a stimulus, device turned, fallback item) never count.
8. **Accessibility**: keyboard play everywhere; touch targets ≥ 44 px; nothing flashes faster than 3 Hz; colour never the only cue; reduced motion respected outside the stimulus itself.
9. **Track** (3D multiple-object tracking) is labelled attention practice and bets on attention control; no stereo, no commercial trainer's name or unit; its speed is in its own unit (cw/s).
10. **Measurement**: near, mid and far probes that are never trained and give no feedback, with alternate forms; baselines before rated training; change judged against the familiarity estimate and the verbal control, never against zero; a check built and simulated to show one player's real gain of a stated size within weeks; an export the community can pool. No IQ, VSI index, percentile, norm or brain age anywhere.
11. **Game layer**: goals and feedback the player sees at once, growth they can watch, variety, results worth sharing, and something new to return for. Each mechanic that research warns about is built as the variant that keeps its draw and drops the harm, with a DECISIONS line naming the harm: nothing pays for time or logins (no lifetime points for right answers; challenge points only in the Daily and the Climb); comparison only through seeded codes and cards, no leaderboards; no Duolingo-style streaks (no daily chain, freezes or "streak about to break"), while the weekly goal keeps its forgiving weeks-in-a-row count; achievements never say "mastered". Nothing decorative runs during a stimulus; celebrations use ink and green, never the accent (the stimulus target colour).
12. **Licences**: code, code comments and code examples MIT (LICENSE: the Chimera community); the guide, its figures, the README, the CHANGELOG and the prose in docs/ CC BY-SA 4.0 (LICENSE-GUIDE.md); no GPL, AGPL or non-commercial code or assets; three.js MIT; IBM Plex OFL.
13. **Privacy** (the owner's standing rules; it overrides everything above): nothing published may lead back to the owner. No owner name, email, timezone, city, country, device or home-folder path in any committed file, commit, page or file metadata; credits name the Chimera community; other people appear only by public handle, as a credit the owner asked for; the owner's words are paraphrased, never quoted; files the owner sends never enter the repository; commits are by `Claude <noreply@anthropic.com>`, made with `TZ=UTC`, and times in files are UTC; never a link to a chat, a session or a private page, so commit messages carry no session-link line (keep `Co-Authored-By`); exports and cards name nobody but the nickname a player chose to enter, and hold no browser string, language or time zone until the player switches device details on. Test data and screenshots are made by simulated players. The playtest report keeps device facts because it goes only to the lead.
14. **Plateaus**: a stall in the trial log triggers a stated change; the player is told what changed and why, and later whether it helped; plateau events go into the record and the export.
15. **Transfer bets**: every training exercise names the one mechanism it bets on (`def.bet`: attention, load, variety, strategy, compare, bridge, produce, calibrate, format); at least one bet is new or under-tested (calibrate); exposure to each bet is logged so pooled exports can test it.
16. **Two-minute start and modes**: a newcomer gets every exercise right within two minutes, checked by a fresh agent who knows nothing but the app (times in the VERIFY file); every mode says in the app when it is the right one, and Today suggests one from the log at a time.

## Working on the code
- `npm install` once (three.js and esbuild, pinned), then `npm test` (= `node tests/node/run.mjs`; filter with names, e.g. `node tests/node/run.mjs rotate engine chimera`).
- Browser tests are Python Playwright: `tests/e2e/pwslot.sh python3 tests/e2e/<file>.py` (pwslot allows two browsers at a time); `tests/run_all.sh` runs everything. The dev harness `tests/dev/harness.html?ex=<id>&seed=<n>&p=<dim:level,…>&v=<variant>` mounts one exercise.
- New script or stylesheet: add it to index.html (PENDING blocks + `python3 tools/sync-index.py`).
- `node tools/build-single.mjs` writes dist/Parallax.html (everything inlined); `python3 tools/shots.py` and `python3 tools/build-pdf.py` rebuild the guide's figures and PDF; `node tools/vendor-three.mjs` rebuilds the three.js subset.
- Changing an exercise's dims or levels incompatibly: bump its `version` (trial logs index exercises as "id@version"); a new lowest band goes through `starter` and the registry's `at` steps, and js/engine/rebase.js converts stored levels.
- New record fields: `store.field` (with a repair function), and `store.exportRule(key, { pooled, private })` for what the community export may carry (no local day keys) and what a backup leaves out.
- Privacy check before every push: once per clone run `git config core.hooksPath tools/githooks`; the pre-push hook runs `python3 tools/privacy_check.py` on exactly what the push publishes (commit data included). Private values live in the git-ignored `.privacy.local` (see the script's header); a full pass is `python3 tools/privacy_check.py --tree <ref>`. Commit with `TZ=UTC git commit …`. A zip comes from tracked files only: `git archive --format=zip --prefix=parallax/ -o parallax.zip HEAD`, then `--zip parallax.zip`.

## Test builds and releases
- Playtest mode (js/ui/playtest.js): `BUILD = 'test'` at the top of the file turns it on by default (three taps after each exercise, a note button, Copy playtest report). At release set `BUILD = 'release'`: it then waits behind its Settings switch, off by default. Its log is a private record field: out of backups unless device details are on, never in the community export.
- Release: `main` gets `build` only with the owner's yes; the owner's release checklist is a tap-through page (pass or fail per line).

## Lessons from building it
- Sandboxed previews: history.replaceState throws, relative hash links navigate the frame away, new tabs and the async clipboard are blocked; always offer Copy, and show the address as text.
- One WebGL context for the whole app (the 17th context silently kills the first); thumbnails are snapshots taken in the ready phase.
- Generic frame-drop rules void too many trials on slow devices; judge what harms the task (Track: sphere jumps larger than about 1.5 diameters).
- A pause during a stimulus must cover the item and make it inert; modals and sheets pause the trial.
- Anything inserted above a drawn screen moves the page through scroll anchoring; insert it before the screen renders. Reloads use manual scroll restoration.
- Hand-set item difficulties are a known limit: the engine's simulations under misspecified difficulty still hold targeting, but the community's pooled exports (Lab → community export) are how the steps should be refitted.
